## OSRSheim Setup Plan

A phased install of ~20 mods that lays Old School RuneScape's progression skeleton — per-skill grinds, level-gated gear, monster levels, rare drops, a bank and marketplace, Slayer bounties, a collection log — over Valheim 1.0. Combat stays Valheim's; everything around it becomes RuneScape. Two players, on a rented dedicated server — the host owns the ruleset.

### What this build delivers

~20 independent skills that train by doing and grind toward a cap (≈99)

Gear and tools locked behind skill levels, tier by tier

Monster names + levels over every creature; loot that scales

OSRS-calibrated drop tables — shared Rare/Gem tables, boss uniques at fixed rates, pets at 1/1000+

Skilling tertiaries: bird-nest and mining-gem analogues (~1/256)

Coins, shops, a banker, quests, and a marketplace

Slayer-style bounties and clue-scroll-style treasure maps

Achievements / collection log / leaderboard

A worn-equipment tab and quick slots

Teleports that feel unlocked, not free

Towns and points of interest worth walking to

Two players in one world, with the server as the single config authority

### What stays Valheim

Real-time stamina/dodge combat — no 0.6 s tick system exists in any maintained mod

No click-to-move, click-to-attack, or auto-retaliate

Combat triangle only loosely approximated

One-roll main tables: creature drop entries roll independently — long-run rates match OSRS exactly, but rare double-uniques can happen

No Prayer drain, Runecraft, Thieving, Hunter, or Firemaking analogues

XP feel via multipliers — not OSRS's exact table (13,034,431 to 99; level 92 is the halfway mark)

## Locked decisions

Defaults are committed so the install is one pass, not a research project. Change any of them before Phase 1 — after that they're wired into configs.

 | Decision | Call | Why

 | Players changed
 | Two, on a rented dedicated server
 | Changed 2026-09-19, before the profile freeze — the right time, since adding a server after Phase 8 would mean unfreezing the build. The design is untouched: an audit of the installed profile found the stack already ServerSync'd (Smoothbrain's Lock Configuration, and [Synced with Server] across EpicLoot, AzuEPI, WackysDatabase, MWL and Almanac), so the host becomes the single config authority and the Gale profile becomes the authoring copy. Loot rates are not recalibrated — see Phase 4.

 | Mod manager
 | Gale, profile OSRSheim
 | Verified today: Gale pulls Thunderstore and Hexium catalogs for Valheim by default, favoring Thunderstore when versions match. r2modman is the fallback (Thunderstore only — Hexium mods by hand).

 | Skill engine
 | Smoothbrain skill suite — skip WackyEpicMMOSystem
 | Many separate grinds is the OSRS feel. EpicMMO is one character level + attribute points; running both means two progression systems fighting for the same space.

 | XP rate
 | Authentic grind: 0.5× per-skill multiplier
 | Stretches the climb toward RuneScape pacing. Drop to 0.25× if it still feels fast; the "respect my time" alternative is 1.5–2×. Starting values — tune in game.

 | Death rules changed
 | Keep skills, drop items
 | Your guide picked Casual (keep gear and skills). But an OSRS death drops your stuff — and Valheim's tombstone run is already a gravestone run. Pick the death-penalty tier that removes skill loss but keeps item drop; fall back to Casual if no tier says that. On a dedicated server this is a launch argument, not a world-creation checkbox — see Phase 8.

 | World order changed
 | Test on a scratch world; create the real world last
 | Your guide installs location packs in Phase 7 onto an existing world — but they only generate on unexplored terrain. Testing on a throwaway ModTest world and creating Gielheim after the full stack is stable means towns generate everywhere from hour zero.

 | Loot engine
 | Drop That — append-only (IDs ≥ 100), time-normalized rates
 | It edits both of Valheim's drop systems, and its v3.x syntax is now fully documented — the old guide's biggest open flag, resolved. Appending above the vanilla indexes preserves every progression drop automatically. Literal OSRS fractions at Valheim kill speeds mean 250-hour boss uniques, so rates are scaled by kills-per-hour (a literal-fractions file ships alongside as a swap-in).

 | EpicLoot's role changed
 | Restricted: treasure maps + bounties only; affix drops zeroed
 | OSRS gear is fixed-stat with no random affixes — Diablo-style magic drops fight the aesthetic. The loot deep-dive demotes EpicLoot from pillar to optional layer; the purist build removes it entirely (Almanac bounties then carry Slayer, and the clue-scroll analogue is lost).

 | Monster levels changed
 | CLLC stars off; all its loot multipliers 1.0
 | OSRS monsters have fixed levels per type — random stars and loot multipliers would silently inflate the calibrated tables. CLLC is kept purely for the name-and-level display, and tested on 1.0 before trusting (one tracker reports it quiet since May 2025).

 | Travel
 | Portals on, but earned
 | XPortal for named destinations + KG Teleporter NPCs as fixed hubs, gated by boss keys or fees ≈ unlockable spellbook teleports / fairy rings. No free fast travel.

 Phase 0

## Back up before touching anything

 Copy the entire Valheim save folder somewhere safe.
 Characters (characters_local) and worlds (worlds_local) both live under it. One command in PowerShell:

 Copy

robocopy "$env:USERPROFILE\AppData\LocalLow\IronGate\Valheim" "$env:USERPROFILE\Desktop\Valheim-backup-2026-09-19" /E

 Steam → Valheim → Properties → Updates → "Only update this game when I launch it".
 Stops Steam from patching the game out from under your pinned mods mid-week. Launching through Gale also avoids mid-session updates.

 Note the escape hatch: Properties → Betas → default_pre1_0.
 If a future patch breaks the stack, this rolls back to the last pre-1.0 build. Everyone on a shared world must roll back together, and Deep North content is lost while you're there.

 Confirm Valheim is installed on the NVMe/SSD — not the G: drive.
 Your G: is the SMR drive from the Dota diagnosis; a ~20-mod stack loads a lot of DLLs and assets at boot. Steam → Properties → Installed Files shows the drive; "Move install folder" fixes it.

Heads-up: the first modded launch is noticeably slower — Defender scans every fresh plugin DLL once. Let it finish; don't force-kill the process.

 Phase 4

## Loot — the OSRS drop engine

Valheim has two loot systems, and the split is lucky: creature drops roll every entry independently (per-item long-run rates match OSRS exactly; only "one item per roll" is lost), while object and skilling drops use a genuinely weighted table — structurally identical to OSRS's main table. Drop That edits both. The model, the math, and the fidelity map live in the loot design reference below.

 Install ASharpPen-Drop_That — a post-Sept-9 build if Gale shows one, else 3.1.4.
 The engine; no better-maintained alternative exists. Latest confirmed release is 3.1.4 (Feb 2026) and a 1.0 republish wasn't verifiable on Sept 19 — 3.1.4 is config-driven and may simply work, so test it. If it's broken on 1.0, this phase pauses until it updates.

 Turn on Drop That's debug dump and harvest real prefab names.
 In the generated drop_that.cfg, enable the [Debug] write-to-file options (exact key names vary by version — enable whatever Write…ToFile entries appear), load a world once, and read the emitted files under BepInEx\. Every creature and object table comes out in ready-to-copy config format with correct 1.0 prefab names, Deep North included. Copy from the dump, never from old wikis — rock prefabs especially shift between patches.

 Install Smoothbrain-CreatureLevelAndLootControl 3.9.9, calibrated flat: all loot / boss-loot / trophy multipliers = 1.0, star spawn chances = 0.
 Keeps names and levels over every monster (red = above you) — the OSRS combat-level look — while killing the two things that would silently distort calibrated tables: random stars and loot multipliers. Caveat: one tracker reports CLLC quiet since May 2025. Test it on your 1.0 patch first; if broken, drop it and carry on — Drop That alone delivers the whole loot design.

 Commit to the time-normalized rate preset (default); park literal fractions in a swap file.
 Valheim kill rates run 4–15× slower than OSRS, so literal fractions turn brutal — a literal 1/512 boss unique is ~256 hours at 2 kills/hour. The formula and worked tables are in the reference. Keep a drop_that.character_drop.literal.cfg variant alongside and enable exactly one of the two.

 Install EpicLoot 0.14.8 in its restricted role — or skip it for the purist build.
 OSRS gear is fixed-stat; random affixes are Diablo. Zero EpicLoot's magic-item drop chances from creatures and chests (its loottables.json / randyknapp.mods.epicloot.cfg), keeping only treasure maps (clue scrolls) and bounties (Slayer). Purist alternative: no EpicLoot at all — Almanac bounties carry Slayer and the clue layer is dropped. Boss uniques come from Drop That at fixed rates either way: vanilla rares, WackysDatabase clones, or Therzie Warfare/Armory gear. Done 2026-09-19 night, the hard way: zeroing Global Drop Rate Modifier was never going to work — the mod's own config says elite and boss drops "come from the loot tables directly and are not affected by this setting". Fixed at the table level instead: 141 loot tables + 157 leveled entries set to Drops: [[0,100]], verified zero can still roll. Treasure maps and bounties were checked first and are completely independent (they pay tokens and RewardCoins directly), so the clue/Slayer layer survives intact.

Iterating: dropthat:reload in the console (add -console to launch options; admin-only on servers) hot-reloads every loot config — a ten-second tuning loop. On the dedicated server that becomes edit → upload → reload, and it is admin-only, so you need an adminlist.txt entry or every tuning pass is a server restart. Fraction cheat sheet: 1/128 = 0.78125 · 1/256 = 0.390625 · 1/512 = 0.1953125 · 1/1000 = 0.1 · 1/5000 = 0.02.

Co-op — rates stay, one question opens. Loot rates are deliberately unchanged for two players: a shared pile split two ways is roughly solo per-player pacing, which is the OSRS-authentic answer — a duo gets drops twice as fast collectively while each player’s own rate stays fixed. What is not established: all 26 boss entries carry DropOnePerPlayer = true (a no-op solo), and whether Drop That rolls ChanceToDrop independently per player or rolls once and hands each player a copy is unverified. Irrelevant for coins; decisive for a 1/512 unique — “each of you has a shot” versus “you both get one or neither does”. Test with a temporary 100% entry, then a temporary 50% entry, both players present.

Test
Spawn-test: spawn Greydwarf 20, bulk-kill, confirm coins and the odd gem land. Temporarily raise one rare to ~50 to prove the entry fires, then restore it. Statistics before calling a rate broken: the first drop lands around N kills for a 1/N rate, but allow ~3×N (≈380 kills gives 95% confidence on 1/128). ## Appendices

 Loot design reference — the OSRS model and the math

### How OSRS actually rolls loot

Always drops: bones/ashes on almost every creature (100%).

Main table: exactly one weighted roll per kill — one item or "nothing"; some bosses roll several times.

Pre-roll uniques: bosses and slayer monsters roll uniques first; the main table only fires if all fail.

Tertiary drops: fully independent side rolls — clue scrolls, pets, champion scrolls; several can land on one kill.

Shared sub-tables: the Rare Drop Table (hit at e.g. 8/128) and Gem table (2/128) nest deeper — mega-rares at 15/128 inside the RDT, a sapphire at 32/128 inside gems with a 63/128 "nothing" slot.

Reference rates: abyssal whip 1/512 · dragon med helm 1/128 on the RDT · gem while Mining 1/256 per action · bird nest 1/256 per log · pets 1/1000–1/5000 · flat rates, no bad-luck protection anywhere.

### Fidelity map

 | OSRS concept | Implementation | Fidelity

 | Always drop (bones) | ChanceToDrop = 100 entries | High

 | Main drop table | Independent CharacterDrop entries with matched per-kill chances — same long-run rate per item | Medium-high mutual exclusivity lost

 | Shared Rare/Gem tables | Named lists via UseDropList, tiered with ConditionGlobalKeys | High

 | Gems while mining (1/256) | Weighted DropTable entries on rock/deposit prefabs | High

 | Bird nests (1/256) | Weighted DropTable entry on tree-log prefabs | High

 | Tertiary pet (1/1000+) | Trophy or WackysDatabase custom item as an independent entry | Medium

 | Boss pre-roll uniques | Fixed-stat items at set rates on the boss's CharacterDrop | High

 | Clue scrolls | EpicLoot treasure maps (restricted install) or Almanac bounties | Medium

 | Noted bulk resources | Large AmountMin/Max + AutoStack = true | High big stacks want a stack-size mod

 | Ring of Wealth | ConditionHasItem on an equipped charm enabling richer entries | Low-medium

 | Slayer-task-only drops | Bounties as a loose analogue — no per-player task-conditional drops exist | Low gap

 | Collection log | Almanac achievements per unique + kill milestones | High

### Never touch these vanilla drops

Appending at IDs ≥ 100 protects them automatically; only override a vanilla index ([Boar.0]) deliberately. The list: Deer Trophy ×2 + Hard Antler (Eikthyr) · Ancient Seed ×3 + Swamp Key (Elder) · Withered Bone ×10 + Wishbone (Bonemass) · Dragon Egg ×3 + Dragon Tear (Moder) · Fuling Totem ×5 (Yagluth) · Sealbreaker fragments + Giant King's Hair (Queen) · Fader's sacrificial items · Malicious Blood ×3 (Kall Fimbulbringer) · Surtling Cores · every boss trophy.

### Rate calibration — the two presets

Valheim chance = OSRS chance × (OSRS kills/hr ÷ Valheim kills/hr), capped so no unique gets commoner than ~1/20. Working assumptions (adjust to your pace): OSRS commons ~300–600 kills/hr, OSRS bosses ~20–40; Valheim commons ~60–120, Valheim bosses ~1–3 including summoning costs.

 | Common monster, OSRS 1/512 | ChanceToDrop | Expected kills | ≈ Hours @ 90/hr

 | Literal | 0.1953125 | 512 | 5.7

 | Time-normalized (default) | 0.859 ~1/116 | 116 | 1.3

 | Boss unique, OSRS 1/512 | ChanceToDrop | Expected kills | ≈ Hours @ 2/hr

 | Literal | 0.1953125 | 512 | 256

 | Time-normalized (default) | 2.94 ~1/34 | 34 | 17

Boss unique-hunting is viable because bosses have no resummon cooldown — the same altar works as often as you have offerings. Unique trophies drop once; everything else repeats. Farm summon materials, not altar mods.

### Loot gaps that stay gaps

Exactly-one-item main-table rolls on creatures — independent rolls match long-run rates; occasional double or zero uniques per kill.

Ring of Wealth's "remove the nothing-slot" mechanic — only approximable.

Per-player Slayer-task-only drops.

Prayer from burying bones — no maintained mod.

Loot visibility windows / despawn timers — leave vanilla; items roll, slide, and sink in a physics world.

 Ironman & Hardcore Ironman rules

Ironman: self-imposed — never open the marketplace or trade; the banker is allowed (it's storage, not commerce). Nothing to install.

Hardcore Ironman: the vanilla Hardcore world modifier + the discipline to delete the character on death — or a permadeath mod if you find one maintained on 1.0 (none was verified in the research pass).

 Troubleshooting & patch survival

Read the log first: BepInEx\LogOutput.log → find the first NullReferenceException → read down the stack to the first frame that isn't UnityEngine or a Valheim namespace (ObjectDB, ZNetScene) — that plugin is the culprit.

After a game patch: update BepInEx first, then Jötunn, then mods one at a time, launching between each. Never restore a whole profile blind.

False corruption: launch-day 1.0 produced scary symptoms from stale plugins (duplicated-looking characters, vanished terrain) that were not save damage. Load the world vanilla before concluding a save is corrupt.

Pins hold: Gale installs exact versions and won't silently update them; launching through Gale also stops Steam patching mid-session.

Rollback: Steam → Properties → Betas → default_pre1_0.
